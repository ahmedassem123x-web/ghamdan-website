## 3. Critical defects

### C-1 — Home header invisible at scroll 0 (desktop + mobile) — CRITICAL
- **Seen:** `docs/qa/desktop-home.png`, `docs/qa/mobile-home.png`, `docs/qa/full-desktop-home.png` — nav items + GHAMDAN wordmark render white-on-white at first paint; only the active «الرئيسية» (blue) and the navy WhatsApp pill are visible. On mobile the burger icon is also white-on-white.
- **Cause (verified in code):** `src/components/Header.tsx` — `transparent = overPhoto && !scrolled`, `overPhoto = Boolean(document.querySelector("[data-photo-hero]"))`; header is `sticky top-0` with `bg-transparent` when transparent. But the hero sits **below** the header in flow (photo starts ~115px down, after the navy TopBar + header), so at scroll 0 the transparent header shows the white page background. Only home uses `variant="center"` (full-bleed photo hero, `data-photo-hero` in `src/components/Hero.tsx:132`); every other page's header is solid white and reads fine.
- **After scrolling** the header becomes solid white and reads correctly (verified in `docs/qa/scroll-home-y1900.png`, `y2700.png`).
- **Fix direction:** make the home header solid from the start, or pull the hero under the header (fixed header + negative margin), or enable transparency only once the hero is actually behind it.

### C-2 — Product-detail copy keys shifted by one on 34 of 38 product pages — CRITICAL (systematic data bug)
- **File:** `src/data/pages.ts`, `productDetail` blocks. **Page code:** `src/app/[locale]/products/[slug]/page.tsx` (fixed keys: k2=benefits heading, k3=gallery caption, k5=inquiry pill, k6–k11=trust cards, k12=overview eyebrow, k13=specs heading, k14=related heading, k15/k16=CTA title/text; k1/k4 unused).
- **Template (correct):** p01, p06, p14, p28 — all 14 used keys match the page code's expectations exactly.
- **Shifted (all 14 used keys wrong):** p02, p03, p04, p05, p07, p08, p09, p10, p12, p13, p15, p16, p17, p18, p19, p20, p21, p22, p23, p24, p25, p26, p27, p29, p31, p32, p33, p34, p35, p36, p37, p38.
- **p11:** shifted on k2 only (minor).
- **Root cause:** the shifted blocks have an extra key at the top — k1 = the CI-02 specs note («نعرض هنا المواصفات الأساسية...»), and for p02/p03/p05/p24/p25 also k2 = «منتج مؤكد عند غمدان.» — pushing every subsequent label one slot down. (Verified with proper block-boundary parsing; an earlier parse that overran block boundaries was discarded.)
- **Visible effect (verified on p02, `deye-sun-sg04lp1-6kw`, in built HTML + screenshots):** overview eyebrow pill reads «السبت – الجمعة»; the spec table sits under heading «نظرة عامة»; related cards sit under heading «المواصفات الفنية»; CTA panel is titled «منتجات ذات صلة»; trust card 1's title is the long inquiry sentence; gallery caption reads «المميزات الرئيسية». The spec table data itself is correct (6 rows + note + warranty line).
- **p38 additionally** has a 404-style string in k2 («ربما نُقل الرابط أو حُذف. عد...») and CTA text in the specs-heading slot.
- **Scope:** affects AR/EN/ZH (shared data keys). Solution-detail copy (`solutionDetail`) was checked and is **not** affected (pumping k1/k2 are the correct CTA title/tagline).
- **Fix:** in the data, remove the extra key(s) from the 34 shifted blocks so keys realign with the p01 template (data fix, not a code fix).

## 4. Major defects

### M-1 — Product hero shows only a tiny Gallery thumbnail, no large product photo
- `src/components/Gallery.tsx` renders a thumbnail grid (`grid-cols-2 md:grid-cols-4`); each product has only ONE image, so the hero shows a single ~130px thumbnail in a mostly empty white hero. Ref 06's dominant element is the big inverter photo. (Gallery image itself is correct: `/images/photos/inverter-unit.webp`, 4/3.)

### M-2 — Home hero too dark vs ref 01
- Center hero (`src/components/Hero.tsx`, `variant="center"`) has a `bg-primary-deep/55` overlay (55% navy) over the correct AI hero (`/images/heroes/hero-villa-mountains.jpg` — white villa + panels + mountains). Ref 01 is bright daylight with dark text on sky; the built hero is dark/moody with white text. The overlay is the cause, not the photo. (Overlay class confirmed in `out/ar.html`.)

### M-3 — Systematic hero-treatment deviation: split heroes where the refs are full-bleed
- About (ref 02), Solutions (ref 03), Projects (ref 05), Contact (ref 07), Pumping (ref 09) all use **split heroes** (title one side, photo card the other). The refs use **full-bleed photo heroes** with the title over the photo. The split heroes are clean and well-executed, but they are a different treatment from the references. This also contradicts the `Hero.tsx` comment (photo-bg for detail pages 06/09/10): pumping (09) and product detail (06) do not use photo-bg heroes either.

### M-4 — Related-product cards all share one photo
- On product detail, the 5kW/8kW/10kW related cards all show the identical curved solar-carport photo. Same reuse pattern on the catalogue grid (4× SUN-SG04LP1 inverters = same carport photo; 2× Deye batteries = same cabinet photo; 3× Jntech pumps = same well photo). Stand-in photos per spec (CI-06), but visually repetitive.

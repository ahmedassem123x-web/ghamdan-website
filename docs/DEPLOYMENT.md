## 1. التشغيل محلياً

الموقع ثابت تماماً — أي خادم ملفات يكفي. لا PHP ولا Node ولا قاعدة بيانات.

```bash
cd ~/workspace/ghamdan-website
python3 -m http.server 8123
# ثم افتح: http://localhost:8123/
```

- يعمل أيضاً مباشرة من `file://` (هكذا جرى الفحص — انظر `TEST_REPORT.md`)،
  لكن خادم HTTP هو الطريقة الصحيحة (بعض السلوكيات تختلف عبر `file://`).
- لا متغيرات بيئة، لا مفاتيح، لا أسرار. الموقع بلا خلفية.
- **إعادة البناء بعد تغيير البيانات:**
  ```bash
  python3 tools/build.py
  ```
  يولّد الصفحات الـ75 من `assets/js/data.js` عبر `tools/sitegen/`.
  لإعادة توليد `data.js` من الجدول:
  ```bash
  python3 tools/extract_catalog.py   # يقرأ xlsx؛ الأسعار تُحذف عند التوليد
  ```
- **الفحص الآلي:**
  ```bash
  node tools/qa_probe.mjs            # 18 صفحة × مقاسين = 36 فحصاً + لقطات
  node tools/qa_one.mjs <page>       # فحص صفحة واحدة
  ```
  يتطلب Chromium في `/opt/meta-chromium/chrome` (بلا رأس، عبر CDP).

## 2. النشر كاستضافة ثابتة (الخطوة التالية)

أي استضافة ثابتة تصلح (GitHub Pages، Vercel Static، Netlify، Cloudflare
Pages، أو أي خادم ويب). المتطلبات:

1. جذر المستودع = جذر الموقع (لا مجلد `public/` منفصل).
2. ارفع كل الملفات كما هي؛ لا خطوة بناء.
3. تأكد من تقديم `assets/fonts/*.woff2` و`assets/js/vendor/*.js` بنفس
   المسارات النسبية (لا CDN).
4. `404.html` في الجذر يعمل تلقائياً كصفحة 404 في GitHub Pages وNetlify.

**قبل أي نشر عام — قائمة منع:**
- [ ] حذف/تنظيف ملاحظات الأسعار الداخلية من `assets/js/data.js`
      (انظر `DATABASE_SCHEMA.md` §5) — قابلة للقراءة من «عرض المصدر».
- [ ] حذف بيانات دخول اللوحة التجريبية من صفحة الدخول ومن `app.js`
      (انظر `ADMIN_GUIDE.md` §1) — أو حجب `admin/` كلياً عن النشر العام.
- [ ] إصلاح مفتاح سجل واتساب (`gts-wa-log` ← `gts-wa-clicks`) إن أُبقيت اللوحة.
- [ ] استبدال الصور البديلة بالصور الحقيقية (CI-06) أو إبقاء شارة
      «معاينة تطويرية» ظاهرة — لا تنشر البدائل كصور حقيقية.
- [ ] موافقة أحمد الصريحة على النشر (قاعدة دائمة: لا نشر بلا إذنه).
